# Glass Edge After Frame Flow

Status: Draft  
Datum: 2026-07-06

## Ziel

AP161 fuehrt die Glass Edge wieder bewusst in den UX-Pfad zurueck. Der Frame-Flow ist stabil genug, damit die Kante nicht mehr nur Effekt ist, sondern die sichtbare Bruecke zwischen Nehmen und Frame.

## Produktregel

RK Workspace zeigt genau eine gläserne Kante zur naechsten passenden Ablage.

Nicht:

- Bubble-Feld
- Radar
- mehrere Portale
- App-Fenster
- technischer Zielbrowser

## Ablauf

1. Der Mensch nimmt ein echtes Ding.
2. Die Shell bestimmt die naechste Ablage.
3. Genau eine gläserne Kante erscheint.
4. Das Ding gleitet in diese Kante.
5. Auf der Gegenseite entsteht ein Frame.
6. Das Original bleibt beim Owner.

## Visuelle Sprache

Die Kante ist:

- gläsern
- ruhig
- raeumlich
- peripher
- erst beim Tragen sichtbar

Sie darf nicht schreien, blinken oder mehrere Moeglichkeiten verkaufen. Sie sagt nur:

```text
Hier geht dein Arbeitsraum weiter.
```

## Verbindung zu FrameOnly

Die Glass Edge bedeutet nicht Dateiuebertragung. Sie bedeutet:

```text
Ein Frame entsteht dort.
```

Der Owner bleibt Besitzer. Die Zielablage bekommt eine sichere Ansicht und keine freie Originaldatei.

## Abbruch

Wenn der Mensch das Ding nicht in die Kante fuehrt, verschwindet die Kante wieder ruhig. Kein Fehlertext, kein Dialog, keine technische Warnung.
