# Visual Reality Blueprint

Dokument-ID: RKWS-VISUAL-REALITY-BLUEPRINT
Version: 1.0.0
Status: Accepted
Datum: 2026-07-04

## Wichtigster Satz

Eine Ablage-Linse ist keine Schaltflaeche.

Sie ist eine lebendige raeumliche Oeffnung zu einer anderen Ablage.

## Ziel

MA006.09 definiert, warum eine Ablage-Linse anders behandelt werden muss als eine UI-Komponente.

Der Mensch soll nicht denken:

```text
Da ist ein Ziel.
```

Sondern:

```text
Dort geht mein Raum weiter.
```

Der Web-/Browser-Prototyp bleibt als technische Testumgebung nuetzlich. Er ist aber kein gueltiger Human-Experience-Testpfad mehr, weil der Owner in Webflaechen kein echtes Raumgefuehl wahrnimmt.

## Was Ist Eine Ablage-Linse?

Eine Ablage-Linse ist eine sichtbare, lebendige Raumoeffnung am Rand einer Ablage.

Sie zeigt nicht:

- Ziel.
- Button.
- Dropzone.
- Status.
- Transfer.

Sie zeigt:

- eine Moeglichkeit.
- Tiefe.
- Richtung.
- eine andere Ablage.
- einen weichen Uebergang.

Eine Linse erscheint erst, wenn der Mensch ein digitales Ding nimmt oder die passende Geste ausloest. Ohne Ding in der Hand soll sie nicht als permanente UI im Raum stehen.

## Warum Gruene Punkte Falsch Sind

Gruene Punkte sind technisch lesbar, aber emotional falsch.

Sie erinnern an:

- Radar.
- Statusanzeige.
- Zielscheibe.
- Online-Indikator.
- Button.
- Programmoberflaeche.

Eine Ablage-Linse muss dagegen wie ein Teil des Raums wirken. Sie darf lesbar werden, aber nicht sofort erklaeren. Sie darf einladen, aber nicht schreien.

## Warum Eine Linse Leben Muss

Eine tote Linse wirkt wie ein Symbol.

Eine lebendige Linse wirkt wie ein Raumphaenomen.

Erlaubt:

- leichte Reflektion.
- minimale Bewegung.
- langsames Atmen.
- feine Wellen.
- sanfte Formveraenderung.
- Perspektivantwort bei Naehe.

Nicht erlaubt:

- hektisches Pulsieren.
- Blinken.
- nervoeses Wackeln.
- Effektfeuerwerk.
- Dauerwabern.

Leitsatz:

```text
Die Linse lebt, aber sie schreit nicht.
```

## Licht, Brechung, Tiefe Und Bewegung

Eine Ablage-Linse braucht mehr als eine Kontur.

Licht zeigt, dass etwas im Raum liegt.

Brechung zeigt, dass man durch etwas hindurchsieht.

Tiefe zeigt, dass hinter der Linse eine andere Ablage liegt.

Bewegung zeigt, dass die Linse auf Naehe antwortet.

Diese vier Qualitaeten erzeugen die Wahrnehmung, dass die Linse nicht gezeichnet ist, sondern im Raum existiert.

## Keine UI-Komponente

Eine Linse darf nicht so gebaut werden, als waere sie:

- Button.
- Kreis.
- Panel.
- Karte.
- Dropzone.
- Kontextmenue.

Eine UI-Komponente fragt:

```text
Was moechtest du anklicken?
```

Eine Ablage-Linse fragt:

```text
Willst du hier etwas ablegen?
```

Der Unterschied ist nicht technisch. Er ist menschlich.

## Rand Der Realen Ablage

Linsen erscheinen am Rand der realen Ablage.

Beispiele:

- Monitor rechts -> Linse rechts.
- Tablet oben rechts -> Linse oben rechts.
- Handy unten -> Linse unten.
- Beamer vorne -> Linse oben/vorne simuliert.

Fuer V1 duerfen diese Positionen simuliert sein. Emotional muss aber gelten:

```text
Dort geht mein Raum weiter.
```

## Sichtbarkeit Erst Bei Geste

Eine Linse ist nicht permanent sichtbar.

Ablauf:

```text
Geste
digitale Haptik
Linsen tauchen langsam auf
Raum wird wahrnehmbar
```

Die Einblendzeit liegt fuer den Spike bei etwa 1 bis 2 Sekunden.

Die Linse erscheint weich, raeumlich und aus dem Rand heraus. Sie erscheint nicht als Popup.

## Moeglichkeit Statt Ziel

Eine Linse ist nicht sofort ein Ziel.

Distanzsprache:

- weit: nur Licht und Andeutung.
- mittlere Naehe: Mikrotext, kaum lesbar.
- nah: Name lesbar.
- sehr nah: Name und `Hier ablegen`.

Diese Lesbarkeit ist Teil des Raumgefuehls. Sie ersetzt technische Zielmarkierung.

## Durch Die Linse Gleiten

Ein digitales Ding darf nicht springen.

Beim Eintritt:

- Ding wird leicht kleiner.
- Ding verschwindet teilweise in der Linse.
- Linse nimmt das Ding weich auf.
- Source-Progress und Target-Progress bleiben wahrnehmbar.

Auf der anderen Ablage:

- Ghost erscheint.
- Ghost wird groesser.
- Ghost wird klarer.
- Ding kommt aus der Linse heraus.
- Ding kann positioniert werden.

Ziel:

```text
Das Ding geht durch den Raum.
```

Nicht:

```text
Das Ding wurde gesendet.
```

## Haptik Als Vierte Dimension

Desktop kann fuer diesen Slice keine echte allgemeine Haptik liefern.

Darum ist optische Haptik Pflicht:

- Widerstand beim Greifen.
- Teilverdeckung.
- Griffschatten.
- Kompression.
- vektorielle Neigung.
- Portal-Sog.
- Ghost auf der Zielablage.

Mobile Ablagen sollen spaeter echte Haptik liefern:

- beim Greifen.
- beim Loesen.
- bei Annaeherung an Linse.
- beim Eintritt in die Linse.
- beim Ablegen.

Haptik ist keine Dekoration. Sie ist die vierte Dimension der digitalen Physik.

## Fuenf Linsen-Hypothesen

MA006.09 prueft fuenf Ansaetze:

- Linse A: Seifenblase, transparent, feiner Rand, Lichtreflex.
- Linse B: Wasserlinse, feine Wellen, ruhiger innerer Glanz.
- Linse C: Glaslinse, klare Tiefe, Lichtkante, Brechung.
- Linse D: Portal-Linse, oeffnender Rand, tiefe Mitte, Mini-Ablage.
- Linse E: Minimaler Raumriss, fast unsichtbar, nur Licht und Tiefe.

Keine dieser Varianten ist final. Sie sind Wahrnehmungshypothesen.

## Renderer-Eignung

MA006.09 nutzt fuer den nativen Spike WinForms/GDI+ mit transparentem Topmost-Fenster.

Bewertung:

| Frage | Aktueller Spike |
| --- | --- |
| Transparenz | Grundsaetzlich ja, aber ueber TransparencyKey begrenzt. |
| Weiche Schatten | Ja, fuer einfache Schatten. |
| Lichtreflexe | Ja, ueber GDI+-Gradienten. |
| Pseudo-3D | Ja, aber nur 2D-Illusion. |
| Animation | Ja, fuer einfache Timer-basierte Bewegung. |
| Maskierung | Begrenzt. Komplexe Masken sind unbequem. |
| Portal-Effekt | Als 2D-Spike ja, als hochwertiges Gefuehl nur begrenzt. |
| Performance | Fuer V1 ausreichend, fuer Shader-/Blur-/Refraction-Effekte nicht final. |

Ehrliche Einschaetzung:

```text
Diese Rendering-Technik reicht fuer einen ersten nativen Wahrnehmungs-Spike.
Sie reicht wahrscheinlich nicht fuer das finale Zielgefuehl hochwertiger lebendiger Linsen aus.
```

Moegliche naechste Renderer:

- Win2D.
- Direct2D.
- Windows Composition API.
- SkiaSharp.
- Unity-Prototyp.
- Unreal-Prototyp.
- Shader-basierter Renderer.
- separater Visual Prototype ausserhalb der aktuellen App.

Wenn die Linse nicht echt wirkt, muss die Rendering-Technik gewechselt werden. Nicht die Vision.

## Nicht-Ziele

MA006.09 baut noch nicht:

- finale Produktphysik.
- echte Desktop-Objekterkennung.
- globale OS-Hooks.
- echte Payload.
- Discovery.
- Pairing.
- Sicherheitsschicht.
- echte mobile Haptik.
- finalen Shader-Renderer.
